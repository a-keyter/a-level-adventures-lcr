# A Level Adventures in the LCR

## Project overview

- This is a TanStack Start + React + TypeScript app for Liverpool City Region students.
- The primary journey is `/` title screen, `/subjects` selection, `/quests/:selectionId` project choices, and `/plan/:choiceId` project plan.
- Use British English in user-facing copy. Ideas and plans are grounded in `src/data/lsip.ts` and the curated subjects in `src/data/subjects.ts`.
- Preserve the friendly retro arcade visual language in `src/styles.css` and the components under `src/components/arcade/`.

## Repository layout

- `src/routes/` contains TanStack file-based routes. Keep route files here and preserve `src/routes/__root.tsx` and its `<Outlet />`.
- `src/components/` contains reusable UI grouped by feature. Prefer extending an existing feature folder over adding a new top-level pattern.
- `src/lib/adventure.functions.ts` contains the validated server functions for generating, caching, loading and selecting adventures.
- `src/lib/adventure-types.ts` contains shared adventure data types.
- `src/integrations/supabase/` contains database clients and generated Supabase integration code.
- `drizzle/` and `supabase/` contain database configuration and migrations.
- `src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it by hand.

## Data and security rules

- Keep `LOVABLE_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` server-side. Never import `client.server.ts` into browser-facing code or expose service-role data.
- Put input validation at server-function boundaries with Zod, and keep database reads/writes inside validated server functions.
- Continue caching subject combinations and project plans by their stable combination/index keys; avoid triggering a new model request when cached data exists.
- Do not loosen the Supabase RLS policies or bypass the existing anonymous-selection/email separation without an explicit requirement.
- Treat AI output as untrusted input: preserve schema validation and verify any new fields before storing or rendering them.

## Working conventions

- Use the `@/*` alias for imports from `src/` and keep TypeScript strictness intact.
- Follow existing Tailwind CSS v4 utilities and CSS variables. Keep layouts mobile-ready and accessible, including keyboard operation and reduced-motion support.
- Use the existing `lucide-react` icons and feature components where applicable rather than introducing parallel UI primitives.
- Do not edit files marked as automatically generated, including Supabase generated clients/middleware and `src/routeTree.gen.ts`, unless regeneration is the intended change.
- Keep changes focused. Do not rewrite published Lovable history, force-push, rebase, amend, or squash existing pushed commits.

## Local development and checks

Install dependencies with `npm i`, then run `npm run dev` for the Vite development server.

Before committing, run:

```sh
npm run lint
npm run build
```

There is no test script currently defined in `package.json`; add focused tests only when the project gains a test runner or the change warrants introducing one.
